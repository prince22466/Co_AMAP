## Research and acceptance loop

1. Reproduce inexpensive baseline observations (both lengths) and inventory production shapes and memory. Use actual worker traces, graph visibility, shape frequencies and bytes, not just import paths or summed kernel shares.
2. Try one reversible hypothesis at a time; start with grouped MM scheduling and real non-KV memory savings. Test direct operator/reference correctness, tails, strides, dtype, graph capture/replay and integration. For memory work, prove ownership/lifetime and full KV contents remain correct through allocation, reuse, cancellation and preemption.
3. Kernel A/B: alternate warm runs, identical inputs and cache/compilation policy, report median/spread and weighted production impact. KV A/B: same flags, quantify available KV bytes/blocks, peak non-KV allocated/reserved, graph pools, safety headroom, running/waiting, preemptions and recomputed tokens. No capacity claim from write-kernel speed alone.
4. Short serving A/B with owned server restarts and identical workload/order/seed; both lengths, including capacity-pressure screen at concurrency 64. Retain low-concurrency results as diagnostics only. A promising candidate must show plausible serving benefit beyond noise and no correctness issues; otherwise revert quickly and try next hypothesis.
5. Only then run untouched external half-run for fresh control and candidate, profiler OFF, two repeats per case, all requests successful. Guard requires confirmed allocation deadline and conservative remaining time; repeat matched A/B across independent server restarts before claiming causal gain. Compare cumulative gain vs original and incremental gain vs latest accepted candidate; test stacked GEMM+KV changes separately. Report full official benchmark and MATH-500 only if actually run.
6. Preserve measured gains even below target, and negative findings. Push tested code separately from evidence on a candidate PR branch; publish evidence-backed candidate PRs as soon as observable improvement is established. Continue until goal verified or actual GPU/credit deadline/blocker; do not auto-merge.
