# v16 Codex Terra 6.1 autoresearch contract

## Objective and acceptance
Historical full-run self-test total tok/s (4K / 16K): v0 1881.95 / 861.88, v14 2817.15 / 2073.93. The v14 MATH-500 result was 95.2%. See [v14 report](../../../submission/v14/report.md) and [raw benchmark results](../../profiling/v14/).
- Full-run target: **4K >=3011.12 tok/s (+60% vs v0); 16K >=2073.93 tok/s with no reproducible regression vs v14; MATH-500 Level 3 (>=95% per v14 report)**. Use unchanged official procedure under comparable conditions. Historical values are self-test references, not organizer-certified scores.
- Development half-run target: 4K candidate/control >=3011.12/2817.15 (~+6.89%) against fresh original-v16 control; 16K candidate/control >=1.0. This is a research proxy, not proof of the full-run target. No 16K loss allowance; a negative/noisy comparison is not a pass. Independently replicate across restarts before calling a gain verified. Evaluate both cumulative vs original and incremental vs accepted parent; do not keep a change that erodes established 16K throughput for a 4K gain.
- Smaller observable 4K wins can be checkpointed in provisional PRs; continue research. Do not claim +60% or final acceptance without unchanged full-run and MATH-500 results. If a reproducible gain cannot be verified before deadline, report the best supported provisional candidate and keep v14 as fallback.

## Research loop
1. Apply [prior-work gate and ranked hypotheses](autoresearch/RESEARCH_QUEUE.md) before GPU experiments. Read relevant v0–v15 outcomes and latest related PRs; do not repeat completed profiling, sweeps, rejected experiments or stacks. Reopen only with specific new evidence/mechanism. Log closest prior outcome, material novelty, missing evidence, smallest decisive test and decision.
2. Re-rank by plausible 4K elapsed-time benefit, production evidence and 16K risk. Collect only missing attribution. One reversible change at a time; direct reference correctness, affected integration/fallbacks and graph replay; verify actual worker source and kernel execution. Alternating warmed kernel A/B with representative production shapes; include complete chain cost.
3. Matched profiler-off serving diagnostics on both lengths, fresh restarts, same seed/order/cache protocol; include concurrency 64 and decode-length screen if needed. Report total tok/s, successful/failed requests, TTFT/TPOT, prefix hits, KV capacity/preemptions, variability. Do not infer whole-run gain from kernel speed. Avoid extra scratch that reduces 16K capacity; no unresolved 16K drop. Default research latency screen: <=5% mean TTFT/TPOT increase per case, plus applicable competition latency limits; the 5% is not an official threshold.
4. Only promising candidates proceed to unchanged two-case half-runs, two repeats per case, all successful, profiler OFF. Reuse a fresh original-v16 control within the same allocation only if hardware/runtime/protocol/source match. Independently replicate matched comparisons across restarts; alternate order between pairs where possible. Test stacked changes separately. Use the read-only evaluator as a numeric screen, not certification. The operator may run final half-runs/full-runs/accuracy manually; coordinate to avoid duplication.
5. Preserve tested source, evidence and negative results in candidate PRs; revert failures. Continue until replicated development target or actual resource deadline/blocker. Keep provisional, replicated half-run and full-run/accuracy status separate.

## Budget and preservation
Use the operator-confirmed allocation deadline before GPU work; never reset during an allocation. Check budget before each diagnostic, allowing time for backup. Half-run historical duration ~90–120 min per two-case run; initial conservative guard requires >=150 min for one, >=275 min for two (90 min alone insufficient). Raise estimate if slower; reserve >=25 min for off-host evidence/PR handoff. If guard refuses or source/worker identity is unverified, do not launch. Checkpoint at start, after valuable/rejected results, before long tests and <=30 min intervals except blocking half-runs (durable start/completion manifests). Commit tested source before server startup; do not edit while serving. Checkpoint helper commits only evidence, but pushing a branch publishes all its unpushed commits. Save raw artifacts off-host; never commit secrets or kill unrelated processes. No GPU allocation or agent starts automatically.
