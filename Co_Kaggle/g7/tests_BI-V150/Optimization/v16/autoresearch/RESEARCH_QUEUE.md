## Ranked starting hypotheses (not results)
1. **4K decode critical path and exact sampler/logits traffic.** Determine actual time share of sampling and vocabulary projection across representative decode graph steps using the smallest missing native timeline/counter probe. Graph visibility gaps are not idle. v15 exact division-argmax candidate (PR #259) showed clean short 4K pressure +3.06%, 16K +2.55% (128 output, matched cache hits), one clean pair only; earlier instrumented 4K +6.03% confounded. If manual v15 half-runs validate it, consider isolated reimplementation/port from v14 under novelty/eligibility and strict 16K gate; if still unverified, leave separate and avoid duplicating ongoing v15 validation. Never port log-domain approximation or global helper mutation changes. Seek new exact reduction/filtering/logits dataflow only where production attribution supports it; preserve top-k/p, RNG state/order, FP rounding/ties/nonfinite semantics and processed outputs.
2. **New small/medium-M GEMM/Linear execution mechanism.** In 4K high-concurrency decode, actual shapes differ from wide prefill. Reuse v7/v15 production shape frequencies and resource tests. Investigate low-M weight traffic, wave underfill, coalesced/vector loads, tensor-core utilization or safe partitioned reduction only if a different measured limitation exists. Include complete scratch/reduction/launch cost and real graph replay. No grouped scheduling, old staging/warps or blind tile sweeps. Preserve BF16, strides, tails, bias and existing dispatch. Large-M GEMM only if new causal evidence beyond v15.
3. **Exact mixed prefill/decode attention dataflow.** v14 specializes pure decode and multi-query batches differently; mixed batches do not use pure-decode page lookup. Inspect actual mixed-row distribution and wasted lanes/resource use; seek new within-operator work elimination e.g. safe per-row extent-aware iteration or masking that avoids provably irrelevant blocks without dropping any valid keys. First check v4/v9/v10/v12 prior experiments; no rerun of their tile/stage/page-index or sparse experiments. Preserve 16K v14 behavior, dense semantics, causal masks, 2D/3D dispatch, graph safety, shuffled pages and tails. If no materially new mechanism, skip.
4. **New cross-operator materialization/launch reduction.** Inspect actual compiled chain (already fused pointwise ops) for avoidable intermediate layout copies, residual/activation traffic or redundant launches not addressed by v3/v15. Compare complete existing production graph, not naive eager surrogate. No repetition of gate/up SwiGLU variants or generic RMSNorm fusion. Prefer no persistent scratch or net memory savings; check 16K block count and preemptions.
5. **Runtime gaps only with causal evidence.** If native trace proves real uncovered host/device sync or launch overhead, remove unnecessary synchronization/copy in owned inference/operator path with unchanged graph and scheduler semantics. No tuning benchmark, changing scheduler admission/policy, graph mode or bypassing selection. If eligibility ambiguous, diagnostic-only.

Start with CPU prior-work audit, then smallest missing attribution for the highest plausible 4K benefit; do not require every direction. Re-rank by measured production time and 16K risk. Candidate changes must be general by shape/layout/resources, never prompt-length/workload hardcoding. 16K capacity work is not a standalone goal; monitor capacity, no regression. Use independent matched screens, no automatic repeat of v15 unfinished work; coordinate any overlap with human. A new mechanism with no evidence of material impact should be abandoned quickly.
