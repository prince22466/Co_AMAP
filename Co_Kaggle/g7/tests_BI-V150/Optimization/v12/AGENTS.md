# v12 sparse-attention experimental contract — Codex / remote researcher

- Work only under `/root/Optimization/v12`. Do not change v0–v11, `/workspace/vllm-plugin-FL/benchmarks`, the dataset, model weights, framework operator-selection logic, or competition vLLM serve flags.
- **Start from v10 operator code, not the unproven v11 MM candidate**. Before any results, record branch SHA, operator hashes, loaded Python module paths, model hash, external benchmark hash, GPU allocation deadline, software/hardware versions.
- A speculative sparse pattern changes model behavior. Do not present an improvement as competition-eligible until unchanged MATH-500 Level 3 passes >=95% **and** separate long-context retrieval/capability tests show no material deterioration **and** the organizer has confirmed eligibility if required. Even passing such tests does not guarantee official acceptance.
- The staged prototype adds `experimental_sparse_window_tokens` and `experimental_sparse_sink_tokens` as explicit Python-operator arguments. Both default to 0. Existing production vLLM wrapper therefore remains **dense**. Test these arguments directly on the candidate first; do **not** report a v12 sparse server speedup until the wrapper is deliberately integrated and a production GPU trace proves sparse tile skipping is active.
- Candidate is BF16, (16 query heads, 2 KV heads, head dim 128), full-causal, normal paged KV prefill only. Preserve decode, mixed batches' single-token decoding, 2D/3D variants, sliding-window, PrefixLM, quant modes, tensor descriptors, Alibi, sinks, softcap, and fallbacks. Do not silently reinterpret an existing model attention mask as approval to approximate it.
- Sparse tile-skipping must happen **before K/V loads and QK/PV dot**, not merely by masking S after the computation. Handle partially retained KV tiles with per-query masks; no duplicated sink/recent tiles, no missing current-token/causal rows, no NaNs, no OOB block-table reads, no hidden GPU sync or device-to-host sequence-length transfer.
- First verify default-off dense regressions on BI-V150, then direct GPU reference vs explicit sparse PyTorch reference for misaligned pages, query tails, nonzero prefix, mixed paging, and zero-sink. Then alternating kernel A/B event timing at actual 4K/16K chunk shapes. Save raw medians, p10–p90, launch counts, tiles visited, registers/SMEM/spills and all numeric errors. No correctness -> no rollout.
- Candidate patterns: W=4096/S=0, W=4096/S=128, W=8192/S=128. Treat them as algorithm research; do not tune to benchmark-specific prompts or accuracy test data. Include 16K evidence retrieval across the skipped-middle region and multiple random seeds. Report failure cases and negative experiments.
- Only after direct tests and good kernel evidence: integrate an explicit source-defined *experimental* serving mode, audit mixed prefill/decode semantics, show the sparse kernel executes, and run same-machine matched short-serving A/B; then, if justified, the unmodified 4K+16K development half-run, no editing scripts or scoring inputs. Independent replicated A/B, success counts, prefix-cache observations, TTFT/TPOT, and accuracy are mandatory.
- Operator correctness and unchanged model behavior are two different properties: a local+prefix sparse result can be correct *for its defined sparse mask* but incorrect for the original dense attention. Document both.
- Keep append-only evidence in `EXPERIMENTS.md` and PR; do not claim remote GPU work happened until actual logs and hashes exist. Save ignored large logs and raw CSVs off instance before expiry. Do not auto-merge.
