## Performance goals and separate validity gates

- **Fixed reported v10 reference**: 4K `[4096,1024,64,256]` **2372.38** Total tok/s; 16K `[16384,1024,64,128]` **1872.70** Total tok/s. Reported v10 MATH-500 97.1% is historical, NOT proof for v12. These reference numbers are **goal anchors, not matched controls**.
- **Minimum**: +5% vs frozen v10 AND independently repeatable >=5% vs freshly measured v12 starting-source control in **either** scenario: 4K >=2490.999 OR 16K >=1966.335; both scenarios must be measured. **Stretch**: +10% => 4K >=2609.618 OR 16K >=2059.970 with matching causal uplift. Reproducible >=3% incremental gain over last accepted matched v12 control is worth a **draft progress PR**, even below minimum. No unapproved material regression in the other scenario or overall performance.
- **Numerical exactness** is the default target: compare attention to the reference dense operator (BF16 tolerances, NaNs, RoPE/causal/paging semantics) for prefill, pure decode and mixed prefill/decode. Genuine exact algorithmic reorganizations (FlashAttention-2, split-K/Flash-Decoding, double-buffering/paged KV tile reuse) outrank approximate algorithms in likelihood of competition compliance.
- **Sparse approximation** is a separate, *conditional* research track. Being correct for a particular sparse mask is NOT being equivalent to original dense attention. Validate vs (1) explicit sparse reference, (2) dense kernel output statistics at relevant layer/token/head shapes, and (3) full MiniCPM long-context behavior: needle/retrieval at beginning, **middle** and end, multiple positions, distractors, reasoned multi-hop queries, 4K/8K/16K and multiple seeds. Preserve original model ability; do not optimize on MATH-500 or change its evaluator. Human performs unchanged official MATH-500 (project threshold >=95%). The competition may reject any material behavior change regardless of passing MATH-500. Flag unresolved sparse eligibility and seek organizer judgment BEFORE promoting such code for submission.
- Production A/B: same source revision controls, exact code/benchmark/model hashes, same GPU, fresh server restarts, alternating A/B order, warmed kernel timing, prefix-cache status, per-run samples, all requests SUCCESS, TTFT/TPOT, total and output tok/s. GPU summed-kernel time is NOT serving wall time. A good isolated kernel speedup is not an accepted serving speedup.

## Prioritized iterative research, no artificial backend switch

1. Profile uncached 4K/16K prefill, mixed prefill/decode, and pure decode; measure attention Q/KV shapes, kernel counts, GPU-summed time versus wall critical path, registers/SMEM/spills, bank conflicts, memory throughput, preemptions and CPU/GPU gaps. CUDA graphs may hide decode kernel work from naive traces. Compute Amdahl estimates and **re-rank the queue** before editing.
2. Exact FlashAttention-style **operator rewrite INSIDE the existing Triton attention**: reduce non-MMA softmax work, reorganize Q/KV warp ownership and staging, improve coalescing/pipeline overlap, retain stable online softmax and v10 fallback/feature paths. v10 already uses a fused tiled online softmax; simply invoking a named FlashAttention implementation is NOT acceptable.
3. Exact paged-KV long-context split-K, sequence-parallel partial attention with numerically correct online-softmax merge, page-index reuse, 2D/3D paths and mixed scheduling. Measure extra scratch traffic/reduction launch cost under concurrency 64. Do not alter operator-selection policy to boost speed.
4. Approximate trials ONLY if exact opportunities are insufficient or estimated gain high: (a) local window+global prefix/attention sinks, (b) blockwise dilated/global anchors, (c) query-aware page top-K based on cheap Q/K summaries such as Quest, (d) hybrid dense prefill + selective decode. Reject candidates with measurable middle-context information loss. Track dense-oracle recall, missing-token cases and model-quality/regression, never selectively choose benchmark prompts.
5. Ring Attention is a **conditional** future research item only for authorized **multi-GPU** hardware with measurable K/V communication; on one BI-V150 GPU there is no ring. If seeking single-GPU stream-level pipelining, describe it as pipelined attention, not distributed Ring Attention.
6. Explore other concrete operator work (K/V paging, double-buffer K/V staging, address generation, mixed-batch data layout, split/reduce) only with a real causal trace, not architecture fashionable labels. Do not merge unrelated hypotheses into one untestable patch.

## Required gates for EACH candidate

- **G0: Evidence and Amdahl** — write current bottleneck share, real shapes, expected benefit and an operator-level proposal, including compatibility and model-quality risk. If no credible impact, reject without coding.
- **G1: Correctness** — isolated operator numerical/fallback tests for full dense features, tails 1/7/9/65/2048, shuffled 16-token KV pages, 4K and 16K chunked prefill, missing/partial pages, segmented decode, long/mixed batches and BF16. For sparse, explicit sparse mathematical reference *and* dense behavior drift. Incorrect -> revert only this candidate.
- **G2: Kernel A/B** — warmed alternating repeatable medians and variability, launch dimensions, memory transactions, actual tile-skip counts, register/SMEM/spills, same GPU tensor values; no benchmarking-script changes. Validate the optimized kernel executes in actual v12 production.
- **G3: Short serving A/B** — paired randomized short tests in 4K and 16K, logs & full error accounting, cache/graph warmups, TTFT/TPOT/output rate, no performance claims from the diagnostic numbers alone.
- **G4: Model-quality and compliance** — dense exact: relevant model functionality smoke and human MATH-500 for selected candidate. Approximate: mandatory long-context tests and written organizer eligibility determination before competition promotion. If accuracy below project minimum or materially weaker retrieval, reject.
- **G5: Unchanged full 4K+16K half-run** — only for a likely positive candidate, after operator-confirmed allocation deadline and `session_budget.py admit`; human-controlled unchanged MATH-500 is separate. Independent A1/B1/A2/B2 half-run replication when allocation permits. A single A/B pair remains provisional.
- **G6: Preservation and promotion** — record negative as well as positive findings; only proven operator deltas and tests enter a draft PR. Never auto-merge or claim a deployment without real production trace. Failed attempts cannot be relabeled.
